# تشفير اليوميات المُدار

هذه ميزة تجريبية في فرع `e2ee-journal-preview`، وتُفعّل بوضع `MAWJ_E2EE_JOURNAL_PREVIEW=1`. لم تخضع لمراجعة أمنية مستقلة.

## تجربة المستخدم

تسجيل الدخول إلى حساب موج هو الخطوة الوحيدة المطلوبة. عند فتح اليوميات ينشئ التطبيق دفترًا مشفّرًا للحساب عند الحاجة، ويحصل المتصفح على مفتاح مؤقت عبر جلسة Django الموثّقة، ثم يفتح التدوينات تلقائيًا. لا توجد عبارة خاصة باليوميات ولا ملف استعادة ولا مفتاح محفوظ في المتصفح.

تُمسح نسخة المفتاح الموجودة في ذاكرة الصفحة عند مغادرتها أو تسجيل الخروج. عند العودة يحصل المتصفح على المفتاح مجددًا بعد التحقق من جلسة الحساب. تغيير كلمة مرور الحساب لا يغيّر مفتاح تشفير اليوميات.

## ما الذي يحميه التصميم؟

- يشتق الخادم مفتاحًا مختلفًا لكل حساب ودفتر باستخدام HMAC-SHA256 وسر ثابت، ثم يستخدم المتصفح AES-256-GCM لتشفير نص التدوينة والنص المنظم والاقتراحات قبل التخزين.
- يستخدم كل حفظ IV عشوائيًا جديدًا، ويرتبط التحقق برقم الحساب ومعرّف الدفتر ومعرّف التدوينة. تخزن قاعدة البيانات `iv` والنص المشفّر بدل النص المقروء.
- يستطيع مستخدم قاعدة البيانات وحدها رؤية البيانات التعريفية والنص المشفّر، ولا يستطيع قراءة نص التدوينة من دون سر الخادم.
- لا يشمل تشفير نص اليوميات الحسابات أو أسماء المستخدمين أو المهام والأهداف والصور والتواريخ وأحجام السجلات. عند قبول اقتراح كمهمة يصبح محتواه مهمة عادية.

هذا **تشفير مُدار بواسطة الخادم وليس تشفيرًا تامًا بين الطرفين**. يستطيع مشغّل يملك الخادم والكود وسر التشفير اشتقاق المفاتيح أو تغيير JavaScript المرسل إلى المتصفح. الهدف هو حماية النص المخزّن عند تسرب قاعدة البيانات وحدها، مع تجربة استخدام بسيطة.

## سر التشفير والنسخ الاحتياطية

يستخدم التطبيق `MAWJ_JOURNAL_KEY` إن ضُبط، وإلا يستخدم `DJANGO_SECRET_KEY`. في الإنتاج يُنصح بإنشاء `MAWJ_JOURNAL_KEY` عشوائي قوي مرة واحدة وحفظه في إعدادات الاستضافة الخاصة والنسخ الاحتياطية الآمنة. **فقد هذا السر أو تغييره يجعل التدوينات المشفّرة غير قابلة للقراءة.** تدوير السر يحتاج خطة لترحيل المفاتيح والبيانات قبل تغييره؛ لا تستبدله مباشرة.

تبقى الآثار السابقة المحتملة في نسخ SQLite وWAL والنسخ الاحتياطية خاضعة لسياسة تشغيل الموقع. حذف سجل من التطبيق ليس محوًا جنائيًا من كل نسخة احتياطية.

## الدفاتر القديمة المقفلة

الدفاتر التي أُنشئت في النسخة السابقة ما زالت تعتمد على عبارة اليوميات أو مفتاح الاستعادة القديم. لا يستطيع التصميم الجديد استرجاع نصها عند فقد الاثنين. تعرض الواجهة خيارًا صريحًا لحذف الدفتر المقفل وبدء دفتر مُدار جديد؛ لا يحدث الحذف تلقائيًا، ولا يحذف الحساب أو المهام العادية.

## الذكاء الاصطناعي

الحفظ وحده لا يحلل النص. وضع Demo يعمل بقواعد محلية داخل المتصفح. عند إعداد Gemini أو OpenAI أو Claude والضغط على زر الاقتراحات، يُرسل نص التدوينة المحددة إلى الخادم والمزوّد؛ يستطيع كلاهما قراءته في تلك اللحظة، وتطبّق سياسة المزوّد واحتفاظه. تعود النتيجة إلى المتصفح لتُحفظ ضمن النص المشفّر. يميّز الاقتراح بين مهمة قصيرة وهدف مستقبلي؛ ولا تُنسخ المهمة أو الهدف إلى قائمته العادية خارج تشفير اليوميات إلا بعد اختيار المستخدم.

## التشغيل المحلي

```powershell
git clone --branch e2ee-journal-preview --single-branch https://github.com/YmamG/Mawj.git mawj-e2ee-preview
cd mawj-e2ee-preview
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:MAWJ_E2EE_JOURNAL_PREVIEW="1"
$env:AI_PROVIDER="demo"
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py runserver
```

افتح `http://127.0.0.1:8000`، وسجّل الدخول، ثم افتح «اليوميات». يجب أن يفتح الدفتر تلقائيًا. أنشئ تدوينة وهمية وانتظر «تم الحفظ»، ثم حدّث الصفحة وسجّل الخروج والدخول للتأكد من الفتح التلقائي.

## التحقق

```bash
python manage.py test --noinput
node scripts/test_vault_crypto.mjs
```

تغطي اختبارات Django المصادقة وCSRF وعزل ملكية المفاتيح واستقرارها وإعادة تعيين الدفتر القديم وسلامة المهام. يغطي اختبار Web Crypto التشفير وفكّه، وتجدد IV، ورفض العبث وتغيير سياق الحساب أو التدوينة. نجاحها لا يعادل تدقيقًا أمنيًا مستقلًا.
